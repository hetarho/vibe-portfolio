# 백지 공포증 깨기 · 1~4시간 강사용 가이드

예시 코드가 있으면 숫자와 글자를 바꿔 응용하지만, 빈 화면 앞에서는 첫 줄을 못 쓰는 학생을 위한 과외 진행표입니다.
멈추는 이유는 머리가 나빠서가 아니라, **문제를 쪼개는 일(논리)** 과 **문법을 떠올리는 일** 을 한꺼번에 하려다 과부하가 걸려서입니다.
그래서 이 코스는 둘을 떼어 놓습니다. 문법은 손이 먼저 기억하게 하고(타자 연습장, Step 1), 논리는 한국어로 먼저 쓰게 합니다(Step 3~5).

원리 설명은 최소로 합니다. "왜 그렇게 돼요?"라는 질문이 나오면 그때 짧게 답합니다. 먼저 묻지 않습니다.

## 준비 · 노트북 한 대, 화면 하나

설치할 것도, 화면을 나눌 것도 없습니다. 학생은 브라우저 안의 코드 칸에 직접 치고 바로 실행합니다.

1. 브라우저 탭 두 개를 엽니다.
   - 탭 1 · 강의 화면 `사이트주소/lesson/js-blank-page-drill` · 교시를 시작할 때와 문제를 처음 소개할 때만 띄웁니다. 숫자 키 `1`~`4`로 각 교시 시작 화면으로 갑니다. 문제 화면의 「Step 1부터 실습 열기」를 누르면 실습이 새 탭으로 열립니다.
   - 탭 2 · 실습 화면 `사이트주소/html-practice/drill/index.html` · 학생이 칠 때는 이 탭에 둡니다. 첫 화면에 그림이 들어간 사용법이 있으니 첫 수업에서는 이 화면을 같이 읽고 시작합니다.
2. 두 탭은 `Ctrl` + `Tab`으로 오갑니다. 키보드는 학생 앞에 두고, 강사는 옆에서 화면을 가리키기만 합니다.
3. 통과 기록과 친 코드는 그 브라우저에만 저장됩니다. 같은 노트북을 다른 학생이 썼다면 코스 첫 화면 맨 아래 「이 브라우저의 기록 모두 지우기」를 누릅니다.
4. 실습 화면은 모두 같은 틀입니다. 처음 들어가면 「사용법」이 저절로 열립니다.
   - 맨 위 동그라미 1~5 : Step 이동. 지금 Step은 노란 테두리, 통과한 Step은 초록색입니다.
   - 검은 상자 : 이번 Step의 규칙
   - 왼쪽 「내 코드」 칸 : 학생이 치는 곳. `Tab`은 두 칸 들여쓰기, `Enter`는 들여쓰기를 이어 줍니다. 친 코드는 저절로 저장되고, 「처음 코드로」를 누르면 처음 상태로 돌아갑니다.
   - 「▶ 실행」(`Ctrl` + `Enter`) : 오른쪽 실행 화면을 새로 만듭니다. 칸에 값을 넣고 버튼을 직접 눌러 봅니다.
   - 빨간 상자 : 코드 오류. **몇 번째 줄인지** 와 한국어 힌트가 나오고, 누르면 그 줄로 커서가 갑니다.
   - 「채점하기」 : 작은 경우를 차례로 넣어 보고 ✔ / ✘ 를 보여 줍니다. 모두 통과하면 화면이 초록색으로 바뀌고 다음 Step 링크가 나옵니다.

개발 서버(`pnpm dev`)로 띄운 `http://localhost:3030/html-practice/drill/`에서도 똑같이 쓸 수 있습니다.

## 다섯 Step 한눈에 보기

| Step | 이름 | 코드 칸에 처음 들어 있는 것 | 학생이 하는 일 | 넘어가는 기준 |
|---|---|---|---|---|
| 1 | 보고 똑같이 치기 | 비어 있음 | 코드 칸 위 정답(복사 막힘)을 보고 한 글자씩 친다 | 채점 통과 |
| 2 | 값과 연산자만 바꾸기 | 완성 코드, 값과 연산자 자리만 `___` | `___`만 바꾼다 | 채점 통과 |
| 3 | 주석 보고 껍데기 채우기 | `if () { } else { }` 껍데기 + 한국어 주석 | 주석 아래에 코드를 쓴다 | 채점 통과 |
| 4 | 주석으로 뼈대 세우기 | 한국어 주석 3~4줄만 | 껍데기부터 치고 주석을 그 안으로 옮긴다 | 채점 통과 |
| 5 | 완전 백지 | 비어 있음 | 체크리스트 순서대로 주석 → 껍데기 → 빈칸 | 정답 보기 없이 채점 통과 |


## 시간 배분

수업 길이가 정해져 있지 않으면 1교시부터 차례로 하고, 끝나는 시간에 맞춰 멈춥니다. 각 교시는 그 자체로 끝맺음이 됩니다.

### 1교시 · if / else 껍데기 손에 익히기 (60분)

| 시간 | 할 일 | 파일 |
|---|---|---|
| 0~5분 | 타자 연습장 패턴 A 다섯 판 | `00-blank.html` |
| 5~10분 | 타자 연습장 패턴 B, C 각 다섯 판 | `00-blank.html` |
| 10~35분 | 인사하기 Step 1 → 5 | `drill/01-greeting/` |
| 35~55분 | 사탕 나누기 Step 1 → 5 (Step 1, 2는 빠르게) | `drill/02-candy/` |
| 55~60분 | 마무리 : 오늘 Step 5를 몇 분 만에 통과했는지 같이 확인 | |

### 2교시 · else if 여러 갈래 (60분)

| 시간 | 할 일 | 파일 |
|---|---|---|
| 0~5분 | 타자 연습장 패턴 C 다섯 판 (1교시보다 빨라졌는지 비교) | `00-blank.html` |
| 5~30분 | 로그인 Step 1 → 5 | `drill/03-login/` |
| 30~55분 | 재고 주문 Step 1 → 5 | `drill/04-stock/` |
| 55~60분 | 인사하기 Step 5만 다시 (1교시 기록과 비교) | `drill/01-greeting/step5.html` |

### 3교시 · for 반복문 공포증 깨기 (60분)

| 시간 | 할 일 | 파일 |
|---|---|---|
| 0~10분 | 타자 연습장 패턴 D(for 껍데기) 다섯 판 | `00-blank.html#D` |
| 10~35분 | 사탕 쏙쏙 Step 1 → 5 | `drill/05-candy-row/` |
| 35~55분 | 스캔 기록 Step 1 → 4 (Step 5는 시간이 남을 때) | `drill/06-scan/` |
| 55~60분 | 사탕 쏙쏙 도전 문제 : `'<li>' + i + '</li>'`로 바꾸면 몇부터 나오는지 | |

### 4교시 · 미니 프로젝트 조립 (60분)

| 시간 | 할 일 | 파일 |
|---|---|---|
| 0~5분 | 타자 연습장 패턴 C, D 각 다섯 판 | `00-blank.html` |
| 5~15분 | 장바구니 화면을 먼저 눌러 보게 하고, 빈칸 개수(코드 칸 위 노란 배지)를 같이 센다 | `drill/07-cart/cart.html` |
| 15~45분 | 코드 칸 맨 위 주석의 조립 순서 ①~⑤대로 채운다. **빈칸 하나 채울 때마다 실행하고 눌러 본다** | |
| 45~55분 | `clearCart` 함수 안을 직접 쓴다 | |
| 55~60분 | 채점 통과 후, 정규 수업의 `lesson/menu.html`이 같은 모양이라는 것을 보여 준다 | |

### 1시간 또는 2시간만 할 때

- **1시간** : 1교시만 합니다. 사탕 나누기가 끝나지 않으면 Step 3까지만 하고, 다음 수업은 사탕 나누기 Step 4부터 시작합니다.
- **2시간** : 1교시 + 2교시. 재고 주문이 남으면 Step 5는 숙제로 줍니다.
- **3시간** : 1~3교시. 스캔 기록 Step 5는 다음 수업의 첫 문제로 남깁니다.

학생이 어떤 Step을 생각보다 쉽게 통과하면 다음 문제로 넘어갈 때 그 Step을 건너뛰어도 됩니다. 반대로 Step 5에서 막히면 다음 문제도 Step 1부터 다 합니다.

## 교시별 발문 예시

답을 알려 주는 질문이 아니라 **학생이 지금 무엇을 해야 할지 스스로 말하게 하는 질문** 입니다.

### 공통 (모든 Step)

- "지금 Step 몇이야? 이번 Step 규칙이 뭐였지?"
- "결과 네모에 무엇이 나와야 해? 문제 설명에서 그 문장을 손가락으로 짚어 볼래?"
- "빨간 상자가 몇 번째 줄이라고 해? 그 줄로 가 보자."

### Step 1 · 보고 치기

- "한 줄 다 치면 위아래 줄을 번갈아 보면서 같은지 확인해 보자."
- "따옴표가 작은따옴표야, 큰따옴표야?" (오타가 많은 곳)
- 다 친 뒤 : "방금 친 것 중에 어떤 줄이 칸에서 값을 꺼내는 줄이야?" 한 줄만 묻고 넘어갑니다. 길게 설명하지 않습니다.

### Step 2 · 값만 바꾸기

- "이 빈칸에는 숫자가 들어가, 글자가 들어가, 기호가 들어가?"
- "비어 있는 글자는 어떻게 쓴다고 했지?" (`''`)
- "1보다 적다는 기호는 어느 쪽으로 벌어져?"

### Step 3 · 주석 보고 채우기

- "이 주석에서 '~면' 앞부분이 어디까지야? 그게 괄호 안에 들어가."
- "이 주석은 칸에서 꺼내는 거야, 화면에 쓰는 거야? 그 줄은 아까 Step 1에서 어떻게 생겼었지?"

### Step 4 · 주석만

- "아직 아무것도 채우지 말고, 껍데기만 먼저 쳐 볼래? 중괄호 짝만 맞게."
- "이 주석 넷 중에 if 괄호 안으로 들어갈 건 몇 번이야? else 안으로 들어갈 건?"

### Step 5 · 백지

- "체크리스트 1번부터. 한국어로 몇 줄이면 될 것 같아?"
- "주석 다 썼으면 소리 내서 읽어 볼래? 그게 맞으면 코드는 거의 다 된 거야."
- 통과 후 : "Step 1이랑 비교하면 뭐가 제일 달랐어?" 학생 말로 정리하게 합니다.

### 3교시 for

- "이 일을 손으로 하면 몇 번 반복해?" → "그 숫자가 `i <` 뒤에 들어가."
- "반복 안에서 그릇이 어떻게 변해? 한 바퀴 돌 때마다 종이에 적어 볼까?" (`html`이 `<li>사탕</li>`, `<li>사탕</li><li>사탕</li>` … 로 늘어나는 것을 직접 적게 합니다)
- "결과 목록에 넣는 줄은 반복 안이야, 밖이야? 안에 넣으면 몇 번 넣게 될까?" (화면 결과는 같습니다. 그릇 변화를 적은 종이를 보며 '다 모은 다음 한 번'이 왜 깔끔한지 말하게 합니다)

### 4교시 조립

- "버튼을 눌렀는데 아무 일도 없으면 제일 먼저 어디를 봐야 해?" (onclick, 빨간 상자)
- "return을 만나면 그 아래 줄은 실행돼, 안 돼?"
- "총액 그릇이 함수 안에 있으면 버튼을 두 번 눌렀을 때 어떻게 돼?"

## 학생이 멈췄을 때

멈추면 바로 도와주지 않습니다. 아래 사다리를 한 칸씩 내려갑니다. 각 칸에서 다시 움직이기 시작하면 거기서 멈춥니다.

1. **10초 기다리기.** 눈이 화면 위에서 움직이고 있으면 생각하는 중입니다. 말을 걸지 않습니다.
2. **Step 묻기.** "지금 Step 몇이야? 이번 Step 규칙을 읽어 줄래?" 규칙을 소리 내어 읽으면 대부분 다시 움직입니다.
3. **한국어로 말하기.** "코드 말고 한국어로, 이 다음에 컴퓨터가 뭘 해야 해?" 말로 하면 주석으로 그대로 쓰게 합니다.
4. **껍데기만.** "내용은 비워 두고 `if () { } else { }`만 쳐 보자." 손이 움직이면 과부하가 풀립니다.
5. **정답 5초 보기.** 화면의 「막혔으면 · 정답 5초 보기」를 학생이 직접 누르게 합니다. 강사가 대신 읽어 주지 않습니다.
6. **한 Step 내려가기.** 그래도 막히면 비난 없이 맨 위 동그라미에서 바로 아래 Step을 엽니다. "한 칸 내려갔다가 다시 올라오자." 내려간 Step을 통과하면 원래 Step으로 돌아옵니다.
7. **타자 연습장으로 리셋.** 표정이 굳었으면 5분 동안 `00-blank.html`에서 지금 필요한 패턴을 다섯 판 칩니다. 끝나면 같은 Step으로 돌아옵니다.

### 하지 않을 것

- 키보드를 뺏어서 대신 치지 않습니다. 고쳐야 할 줄은 손가락으로 가리키기만 합니다.
- "이건 쉬운 건데", "아까 했잖아"라고 말하지 않습니다. 백지 공포가 있는 학생에게 이 말은 다음 멈춤을 부릅니다.
- 오류가 났을 때 바로 원인을 말하지 않습니다. 빨간 상자의 줄 번호까지만 같이 봅니다.
- Step 1~2에서 원리를 길게 설명하지 않습니다. 설명은 Step 5를 통과한 뒤 학생이 물어볼 때 합니다.

### 자주 나오는 막힘

| 증상 | 화면에 보이는 것 | 짧게 던질 말 |
|---|---|---|
| `if ()` 괄호를 비운 채 실행 | 빨간 상자 · 문법 오류 · 그 줄 번호 | "괄호 안에 들어갈 '~면'은 어느 주석에 있어?" |
| `___`을 그대로 둠 | 노란 배지 「남은 빈칸 N개」, 채점 ✘ "빈칸 ___ 이 남아 있습니다" | "노란 배지 숫자를 0으로 만들어 보자." |
| `.value`를 빠뜨림 | 결과에 `[object HTMLInputElement]님` | "칸을 꺼냈어, 칸에 적힌 글자를 꺼냈어?" |
| `Number`를 빠뜨림 | 이 코스의 문제는 빼도 대부분 맞게 나와서 모르고 지나갑니다 | "왜 `Number`를 썼어? 빼면 어떻게 돼?" 정규 수업 `lesson/menu.html`에서 `04000`처럼 글자가 이어 붙는 것을 직접 보게 합니다 |
| `=`과 `==` 혼동 | 언제나 같은 갈래로만 감 | "같은지 묻는 기호는 몇 개짜리였지?" |
| `stock`을 함수 안에 만듦 | 재고가 계속 7에서 시작, 채점 ✘ "준비" | "버튼을 누를 때마다 처음 값으로 돌아가는 그릇이 어디 있어?" |
| `const`로 만든 그릇을 바꿈 | 빨간 상자 "const로 만든 그릇은 값을 바꿀 수 없습니다" | "이 그릇은 나중에 값이 바뀌어? 그럼 let이야, const야?" |
| 결과 넣는 줄을 for 안에 넣음 | 화면도 채점도 똑같이 통과 | 통과는 인정하고, "이러면 몇 번 넣는 거야? 반복이 다 끝난 다음에 한 번만 넣으면?" 하고 비교해 보게 합니다 |
| 버튼에 onclick 안 걸음 (4교시) | 눌러도 반응 없음, 채점 첫 줄 ✘ | "버튼을 누르면 어떤 함수가 실행돼?" |

## 기록해 둘 것

수업이 끝나면 아래 세 가지를 적어 둡니다. 다음 수업 시작 지점을 정할 때 씁니다.

- 문제마다 통과한 Step (목록 화면에서 초록 동그라미로 보입니다. 같은 브라우저에서만 남습니다)
- Step 5에서 정답 보기를 몇 번 눌렀는지
- 타자 연습장의 첫 판과 마지막 판 시간 (같은 패턴에서 줄어들고 있으면 손이 기억하기 시작한 것입니다)

## 4교시 다음

4교시까지 끝나면 정규 수업 자료로 넘어갑니다. 모든 `lesson/` 파일의 script 안에는 같은 3단계 틀(재료 준비 → 껍데기 먼저 → 빈칸 채우기)이 들어 있습니다.
추천 순서는 `lesson/menu.html`(장바구니와 같은 모양) → `lesson/stock.html`(재고 주문과 같은 문제, 알림창 버전) → `lesson/attend.html`(스캔 기록의 다음 단계)입니다.
