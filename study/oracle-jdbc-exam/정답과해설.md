# Oracle SQL~JDBC 시험 대비 정답과 해설

문제 번호는 [문제집](./문제집.md)과 같다. SQL 작성형은 동등하게 동작하는 다른 SQL도 정답이다. 각 문항은 독립적이며, 같은 이름의 테이블을 생성하거나 변경하는 문항을 순서대로 실행할 필요는 없다.

## A. 데이터베이스와 SQL 기초 (1~10)

1. **데이터**는 관찰·측정한 원래 값이고, **정보**는 그 데이터에 의미를 부여한 결과다.
2. 운영: 조직 업무에 쓰는 데이터. 공용: 여러 사용자·시스템이 공유. 통합: 중복을 줄여 일관되게 구성. 저장: 저장장치에 기록.
3. 추출: 조회. 조작: 삽입·수정·삭제. 정의: 구조 생성·변경·삭제. 제어: 권한·보안·백업·회복·동시성 관리.
4. **Structured Query Language**.
5. DQL: `SELECT`. DML: `INSERT`, `UPDATE`, `DELETE`. DDL: `CREATE`, `ALTER`, `DROP`. TCL: `COMMIT`, `ROLLBACK`.
6. **Result Set**(결과 집합).
7. 기본키는 각 행을 유일하게 식별하며 NULL과 중복을 허용하지 않는다. 외래키는 다른 테이블의 기본키·고유키를 참조해 테이블 간 참조 무결성을 지킨다.
8. `NULL`.
9. Oracle 18c XE: DBMS. SQL Developer: DB에 접속해 SQL을 작성·실행하는 그래픽 도구. SQL*Plus: 명령행에서 접속·SQL 실행을 하는 도구.
10. `SELECT * FROM EMPLOYEE;`

## B. 기본 SELECT와 조건 검색 (11~28)

11. `SELECT EMP_NAME, SALARY FROM EMPLOYEE;`
12. `SELECT EMP_NAME, SALARY * 12 AS 연봉 FROM EMPLOYEE;`
13. 조회 결과에서 같은 값의 중복을 제거한다. 여러 열을 함께 쓰면 그 열들의 조합이 같은 행을 제거한다.
14. `SELECT DISTINCT DEPT_CODE FROM EMPLOYEE;`
15. `SELECT EMP_NAME, SALARY FROM EMPLOYEE WHERE SALARY >= 3000000;`
16. `SELECT EMP_NAME FROM EMPLOYEE WHERE DEPT_CODE IN ('D5','D6') AND SALARY > 3000000;`
17. **AND가 먼저**다. `WHERE (DEPT_CODE = 'D5' OR DEPT_CODE = 'D6') AND SALARY > 3000000`.
18. `SELECT EMP_NAME FROM EMPLOYEE WHERE SALARY BETWEEN 3000000 AND 5000000;`
19. (a) `%`, (b) `_`.
20. `SELECT EMP_NAME FROM EMPLOYEE WHERE EMP_NAME LIKE '김%';`
21. `SELECT EMP_NAME, EMAIL FROM EMPLOYEE WHERE EMAIL LIKE '___#_%' ESCAPE '#';` 앞의 `_` 세 개는 각각 한 글자, `#_`는 실제 밑줄 문자다.
22. `SELECT EMP_NAME FROM EMPLOYEE WHERE BONUS IS NULL;`
23. `NULL = NULL` → UNKNOWN, `NULL <> 1` → UNKNOWN, `NULL IS NULL` → TRUE.
24. `SELECT EMP_NAME || '님' FROM EMPLOYEE;`
25. **포함하지 않는다.** NULL과 비교한 `IN`/`NOT IN`은 UNKNOWN이므로 `WHERE`를 통과하지 못한다.
26. `SELECT EMP_ID, EMP_NAME FROM EMPLOYEE WHERE DEPT_CODE IN ('D1','D3','D5');`
27. `SELECT EMP_NAME, BONUS FROM EMPLOYEE WHERE EMP_NAME LIKE '%수%' AND BONUS IS NOT NULL;`
28. `SALARY AS 월급` 뒤의 쉼표를 지우고, `BONUS = NULL`을 `BONUS IS NULL`로 바꾼다. 정답: `SELECT EMP_NAME, SALARY AS 월급 FROM EMPLOYEE WHERE BONUS IS NULL;`

## C. 함수 (29~52)

29. 단일 행 함수는 입력 행마다 한 결과를 만들고, 그룹 함수는 전체 행 또는 각 그룹을 묶어 한 결과를 만든다.
30. (a) `LENGTH`, (b) `LENGTHB`. 영문/한글의 실제 바이트 수는 문자 집합에 따라 달라진다.
31. `BASE`.
32. `4`.
33. `SELECT SUBSTR(EMP_NAME,1,2) FROM EMPLOYEE;`
34. `ORACLE`.
35. `'SQL'`(양쪽 공백 제거).
36. `'1200'`, `'00012'`.
37. `A-B-C`.
38. `SELECT SUBSTR(EMAIL,1,INSTR(EMAIL,'@')-1) FROM EMPLOYEE;`
39. `2`.
40. 차례대로 `125.7`, `125.6`, `126`, `-3`.
41. `ROUND`는 지정 자리에서 반올림, `TRUNC`는 지정 자리 이후를 0 방향으로 잘라냄, `FLOOR`는 해당 수 이하의 가장 큰 정수로 내림한다. 음수에서 `TRUNC(-2.1)=-2`, `FLOOR(-2.1)=-3`이다.
42. `SYSDATE`.
43. `SELECT EMP_NAME, ADD_MONTHS(HIRE_DATE,6) FROM EMPLOYEE;`
44. `SELECT EMP_NAME, LAST_DAY(HIRE_DATE) FROM EMPLOYEE;`
45. `SELECT EMP_NAME, EXTRACT(YEAR FROM HIRE_DATE) FROM EMPLOYEE;`
46. `SELECT EMP_NAME, TO_CHAR(HIRE_DATE,'YYYY-MM-DD') FROM EMPLOYEE;`
47. `TO_DATE('2024-03-15','YYYY-MM-DD')`.
48. `SELECT NVL(BONUS,0) FROM EMPLOYEE;`
49. `SELECT EMP_NAME, (SALARY + SALARY * NVL(BONUS,0)) * 12 AS ANNUAL_PAY FROM EMPLOYEE;`
50. `DECODE(DEPT_CODE,'D1','본부','D2','지사','기타')`.
51. `CASE WHEN SALARY >= 5000000 THEN '상' WHEN SALARY >= 3000000 THEN '중' ELSE '하' END`.
52. ID 1의 `PAY=10`, ID 2의 `PAY=NULL`. `200 * NULL`은 NULL이다.

## D. 정렬·집계·그룹·집합 (53~68)

53. `SELECT EMP_NAME, SALARY FROM EMPLOYEE ORDER BY SALARY DESC NULLS LAST, EMP_NAME ASC;`
54. `WHERE`는 그룹을 만들기 전 개별 행을, `HAVING`은 `GROUP BY` 이후 집계 결과를 기준으로 그룹을 걸러 낸다.
55. `SELECT COUNT(*) FROM EMPLOYEE;`
56. 차례대로 `4`, `3`, `2`. `COUNT(DEPT)`는 NULL을 세지 않는다.
57. `SELECT DEPT_CODE, COUNT(*) FROM EMPLOYEE GROUP BY DEPT_CODE;`
58. `SELECT DEPT_CODE, ROUND(AVG(SALARY),1) FROM EMPLOYEE GROUP BY DEPT_CODE ORDER BY DEPT_CODE;`
59. `SELECT DEPT_CODE, COUNT(*) AS 인원, AVG(SALARY) AS 평균급여 FROM EMPLOYEE WHERE SALARY >= 3000000 GROUP BY DEPT_CODE HAVING COUNT(*) >= 2;`
60. 집계하지 않은 `DEPT_CODE`를 집계 결과와 함께 선택하므로 그룹 기준이 필요하다. `SELECT DEPT_CODE, SUM(SALARY) FROM EMPLOYEE GROUP BY DEPT_CODE;`
61. `(D1,300)`, `(D2,300)`, `(NULL,400)` 순서다.
62. `AVG(BONUS)=0.15`, `AVG(NVL(BONUS,0))=0.075`. 첫 식의 분모는 2, 두 번째는 4다.
63. `SELECT MAX(SALARY), MIN(SALARY) FROM EMPLOYEE;`
64. `SELECT DEPT_CODE, COUNT(BONUS) FROM EMPLOYEE GROUP BY DEPT_CODE;` `COUNT(BONUS)`는 NULL을 제외하므로 0도 반환한다.
65. (a) `UNION`, (b) `UNION ALL`, (c) `INTERSECT`, (d) `MINUS`.
66. `UNION`은 1행, `UNION ALL`은 2행.
67. `SELECT DEPT_CODE, SUM(SALARY) AS TOTAL FROM EMPLOYEE GROUP BY DEPT_CODE HAVING SUM(SALARY) > 10000000 ORDER BY TOTAL DESC;`
68. `SELECT DEPT_CODE, JOB_CODE, AVG(SALARY) FROM EMPLOYEE GROUP BY GROUPING SETS ((DEPT_CODE,JOB_CODE),(DEPT_CODE));`

## E. JOIN (69~88)

69. 공통된 조건을 이용해 둘 이상의 테이블에 흩어진 열과 행을 하나의 결과로 조회한다.
70. INNER JOIN은 일치하지 않는 왼쪽 행을 제외한다. LEFT OUTER JOIN은 남기고 오른쪽 열을 NULL로 채운다.
71. `SELECT E.EMP_NAME, D.DEPT_TITLE FROM EMPLOYEE E JOIN DEPARTMENT D ON E.DEPT_CODE = D.DEPT_ID;`
72. `SELECT E.EMP_NAME, D.DEPT_TITLE FROM EMPLOYEE E LEFT JOIN DEPARTMENT D ON E.DEPT_CODE = D.DEPT_ID;`
73. `SELECT E.EMP_NAME, J.JOB_NAME FROM EMPLOYEE E JOIN JOB J USING (JOB_CODE);`
74. `ON`은 원하는 조인 조건을 직접 쓴다. `USING(열)`은 양쪽에 이름이 같은 조인 열을 지정할 때 쓴다. `USING`으로 지정한 열은 결과에서 한 열로 합쳐지며, 참조할 때 테이블 별칭을 붙이지 않는다.
75. `3 × 4 = 12`행.
76. `SELECT D.DEPT_TITLE, E.EMP_NAME FROM DEPARTMENT D LEFT JOIN EMPLOYEE E ON D.DEPT_ID = E.DEPT_CODE;`
77. `SELECT E.EMP_NAME, D.DEPT_TITLE, L.LOCAL_NAME FROM EMPLOYEE E JOIN DEPARTMENT D ON E.DEPT_CODE = D.DEPT_ID JOIN LOCATION L ON D.LOCATION_ID = L.LOCAL_CODE;`
78. `SELECT E.EMP_NAME AS 직원, M.EMP_NAME AS 관리자 FROM EMPLOYEE E LEFT JOIN EMPLOYEE M ON E.MANAGER_ID = M.EMP_ID;`
79. 한 테이블을 역할이 다른 두 테이블처럼 연결하는 것이다. 예: 직원 `E`, 관리자 `M`처럼 서로 다른 별칭을 붙인다.
80. `JOB_CODE`가 양쪽 테이블에 있으므로 `E.JOB_CODE`처럼 한쪽을 지정한다. 예: `SELECT E.EMP_NAME, E.JOB_CODE FROM EMPLOYEE E JOIN JOB J ON E.JOB_CODE=J.JOB_CODE;`
81. `SELECT E.EMP_NAME, E.SALARY, J.JOB_NAME FROM EMPLOYEE E JOIN JOB J ON E.JOB_CODE=J.JOB_CODE WHERE E.JOB_CODE='J2';`
82. `SELECT E.EMP_NAME, NVL(D.DEPT_TITLE,'미배치') AS 부서명 FROM EMPLOYEE E LEFT JOIN DEPARTMENT D ON E.DEPT_CODE=D.DEPT_ID;`
83. LEFT는 왼쪽의 모든 행, RIGHT는 오른쪽의 모든 행, FULL은 양쪽의 모든 행을 남긴다. 일치하지 않는 반대쪽 열은 NULL이다.
84. `FROM EMPLOYEE E JOIN SAL_GRADE G ON E.SALARY BETWEEN G.MIN_SAL AND G.MAX_SAL`.
85. `SELECT A.EMP_ID, B.EMP_ID FROM EMPLOYEE A JOIN EMPLOYEE B ON A.DEPT_CODE=B.DEPT_CODE AND A.EMP_ID < B.EMP_ID;` `<` 조건으로 자기 자신과 역순 중복을 제외한다.
86. 의도하지 않은 카테시안 곱이 발생해 양쪽 행의 모든 조합이 만들어질 수 있다. 한쪽이 N행, 다른 쪽이 M행이면 N×M행이다.
87. `SELECT E.EMP_NAME, J.JOB_NAME, D.DEPT_TITLE FROM EMPLOYEE E JOIN JOB J ON E.JOB_CODE=J.JOB_CODE LEFT JOIN DEPARTMENT D ON E.DEPT_CODE=D.DEPT_ID;`
88. `SELECT D.DEPT_ID, D.DEPT_TITLE, COUNT(E.EMP_ID) AS EMP_COUNT FROM DEPARTMENT D LEFT JOIN EMPLOYEE E ON D.DEPT_ID=E.DEPT_CODE GROUP BY D.DEPT_ID,D.DEPT_TITLE;` `COUNT(*)`는 직원 없는 부서도 1로 셀 수 있으므로 쓰지 않는다.

## F. SUBQUERY와 순위 (89~106)

89. 다른 SQL 문 안에 괄호로 넣는 SELECT 문이다. 메인 쿼리의 조건·값·조회 대상으로 사용할 수 있다.
90. 단일 행은 한 행, 다중 행은 여러 행을 반환한다. 다중 열은 두 열 이상을 반환하며 행의 수와는 별개다. 다중 행·다중 열을 동시에 만족할 수도 있다.
91. `SELECT EMP_NAME, SALARY FROM EMPLOYEE WHERE SALARY > (SELECT AVG(SALARY) FROM EMPLOYEE);`
92. `SELECT EMP_NAME FROM EMPLOYEE WHERE SALARY = (SELECT MAX(SALARY) FROM EMPLOYEE);`
93. 서브쿼리가 여러 행을 반환할 때 `=`는 단일 값만 기대하므로 오류가 날 수 있다. `WHERE SALARY IN (SELECT SALARY FROM EMPLOYEE WHERE DEPT_CODE='D1')`.
94. `SELECT EMP_NAME, SALARY FROM EMPLOYEE WHERE (DEPT_CODE,SALARY) IN (SELECT DEPT_CODE,MAX(SALARY) FROM EMPLOYEE GROUP BY DEPT_CODE);` 부서 코드가 NULL인 행은 `NULL=NULL`이 UNKNOWN이어서 빠진다. NULL 부서까지 포함하려면 96번처럼 상관식과 NULL 처리를 따로 설계해야 한다.
95. 상관 서브쿼리는 바깥 쿼리의 열을 참조해 바깥 행에 따라 결과가 달라진다. 비상관 서브쿼리는 바깥 행을 참조하지 않는다.
96. `SELECT E.EMP_NAME,E.DEPT_CODE,E.SALARY FROM EMPLOYEE E WHERE E.SALARY > (SELECT AVG(X.SALARY) FROM EMPLOYEE X WHERE X.DEPT_CODE=E.DEPT_CODE);` 부서 코드가 NULL인 직원은 위 비교에서 제외된다.
97. `SELECT D.DEPT_TITLE FROM DEPARTMENT D WHERE EXISTS (SELECT 1 FROM EMPLOYEE E WHERE E.DEPT_CODE=D.DEPT_ID);`
98. `SELECT D.DEPT_TITLE FROM DEPARTMENT D WHERE NOT EXISTS (SELECT 1 FROM EMPLOYEE E WHERE E.DEPT_CODE=D.DEPT_ID);`
99. 비교 목록에 NULL이 있으면 일치하지 않는 값도 결과가 UNKNOWN이 되어 `NOT IN`에서 행이 빠질 수 있다. 서브쿼리에서 NULL을 제외하거나 `NOT EXISTS`를 사용한다.
100. `SELECT EMP_NAME,SALARY FROM (SELECT EMP_NAME,SALARY FROM EMPLOYEE ORDER BY SALARY DESC NULLS LAST,EMP_ID ASC) WHERE ROWNUM <= 3;`
101. 보장하지 않는다. `ROWNUM <= 3`으로 먼저 고른 행만 나중에 급여순으로 정렬하기 때문이다. 먼저 정렬한 인라인 뷰 바깥에서 `ROWNUM`을 적용해야 한다.
102. **인라인 뷰(Inline View)**.
103. `WITH 이름 AS (SELECT ...)`로 중간 결과에 이름을 붙여 메인 SQL에서 재사용하면 긴 서브쿼리를 반복 작성하지 않아도 된다.
104. `RANK`: `1,1,3`. `DENSE_RANK`: `1,1,2`.
105. `SELECT EMP_NAME,DEPT_CODE,SALARY FROM (SELECT E.EMP_NAME,E.DEPT_CODE,E.SALARY,RANK() OVER (PARTITION BY DEPT_CODE ORDER BY SALARY DESC NULLS LAST) AS RN FROM EMPLOYEE E) WHERE RN=1;` `PARTITION BY`는 NULL 부서도 하나의 구획으로 묶는다.
106. `SELECT DEPT_CODE,SUM(SALARY) AS TOTAL FROM EMPLOYEE GROUP BY DEPT_CODE HAVING SUM(SALARY) > (SELECT SUM(SALARY)*0.2 FROM EMPLOYEE);`

## G. DDL과 제약 조건 (107~126)

107. `CREATE`: 객체 생성, `ALTER`: 객체 구조 변경, `DROP`: 객체 삭제.
108. `CHAR(10)`은 고정 길이 문자형으로 짧은 값을 넣어도 선언 길이에 맞춰 공백이 붙는다. `VARCHAR2(10)`은 가변 길이 문자형으로 실제 값의 길이에 따라 저장한다. 길이 단위는 선언 방식·설정에 따라 BYTE 또는 CHAR다.
109. `CREATE TABLE MEMBER (ID VARCHAR2(20), NAME VARCHAR2(30), AGE NUMBER);`
110. `DATE`, `TIMESTAMP`.
111. `NOT NULL`: NULL 불가, 중복 허용. `UNIQUE`: 중복된 비NULL 값 불가, NULL 허용. `PRIMARY KEY`: NULL과 중복 모두 불가.
112. `CREATE TABLE MEMBER (ID VARCHAR2(20) PRIMARY KEY, NAME VARCHAR2(30));`
113. 두 열 이상을 묶어 행을 유일하게 식별하는 기본키다. 한 테이블에 기본키 제약 조건은 **하나**만 선언할 수 있지만, 그 하나가 여러 열로 구성될 수 있다.
114. `CREATE TABLE TEAM (TEAM_ID NUMBER PRIMARY KEY);` 다음 `CREATE TABLE PLAYER (PLAYER_ID NUMBER PRIMARY KEY, TEAM_ID NUMBER REFERENCES TEAM(TEAM_ID));`
115. 99는 **불가능**(부모 키가 없음), NULL은 **가능**(별도 `NOT NULL`이 없음).
116. `ON DELETE SET NULL`: 자식 행은 남기고 외래키를 NULL로 변경. `ON DELETE CASCADE`: 참조 중인 자식 행도 삭제.
117. `CREATE TABLE PLAYER (PLAYER_ID NUMBER PRIMARY KEY, AGE NUMBER CHECK (AGE >= 0));` `AGE`의 NULL까지 막으려면 `NOT NULL`도 추가해야 한다.
118. `COMMENT ON COLUMN MEMBER.ID IS '회원번호';`
119. `ALTER TABLE MEMBER ADD (PHONE VARCHAR2(20));`
120. `ALTER TABLE MEMBER MODIFY (NAME VARCHAR2(50));`
121. `ALTER TABLE MEMBER DROP COLUMN PHONE;`
122. `ALTER TABLE MEMBER RENAME COLUMN NAME TO MEMBER_NAME;`
123. `ALTER TABLE MEMBER RENAME TO MEMBER_OLD;`
124. `ALTER TABLE MEMBER ADD CONSTRAINT MEMBER_PK PRIMARY KEY (ID);`
125. 조회한 열의 이름·자료형과 조회 결과 행이 복제된다. 직접 선택한 열의 `NOT NULL`은 유지될 수 있으나, 기본키·외래키·고유키·CHECK 같은 제약은 일반적으로 복제되지 않는다.
126. `CREATE TABLE EMP_EMPTY AS SELECT EMP_ID,EMP_NAME,SALARY FROM EMPLOYEE WHERE 1=0;`

## H. DML과 트랜잭션 (127~138)

127. `INSERT`: 행 추가, `UPDATE`: 기존 행 값 수정, `DELETE`: 행 삭제.
128. `INSERT INTO MEMBER (ID,NAME,AGE) VALUES ('u1','가람',20);`
129. 테이블의 **모든 열에 대해** 정의된 열 순서에 맞는 값을 제공해야 한다. 열이 추가되거나 순서가 달라지면 의도와 다른 결과나 오류가 생길 수 있다.
130. `INSERT INTO EMP_D1 (EMP_ID,EMP_NAME) SELECT EMP_ID,EMP_NAME FROM EMPLOYEE WHERE DEPT_CODE='D1';`
131. `UPDATE MEMBER SET AGE=21 WHERE ID='u1';`
132. `DELETE FROM MEMBER WHERE AGE<18;`
133. `UPDATE`는 모든 행의 지정 열을 바꾸고, `DELETE`는 모든 행을 삭제한다.
134. 둘 다 행을 없애고 테이블 구조는 남긴다. `DELETE`는 DML로 확정 전에는 `ROLLBACK`할 수 있다. `TRUNCATE`는 DDL이고 암묵적으로 커밋되므로 `ROLLBACK`으로 복구할 수 없다.
135. 확정: `COMMIT`; 되돌림: `ROLLBACK`.
136. **남지 않는다.** 확정 전 삽입은 `ROLLBACK`으로 취소된다.
137. `UPDATE EMPLOYEE SET SALARY=(SELECT AVG(SALARY) FROM EMPLOYEE) WHERE EMP_ID=100;`
138. `INSERT ALL WHEN DEPT_CODE='D1' THEN INTO EMP_D1 (EMP_ID,EMP_NAME) VALUES (EMP_ID,EMP_NAME) ELSE INTO EMP_OTHER (EMP_ID,EMP_NAME) VALUES (EMP_ID,EMP_NAME) SELECT EMP_ID,EMP_NAME,DEPT_CODE FROM EMPLOYEE;`

## I. SEQUENCE (139~146)

139. 다음 번호를 순차적으로 만드는 데이터베이스 객체다. 키 값 발급 등에 쓴다. 시퀀스 값은 롤백해도 되돌아가지 않으므로 빈 번호가 생길 수 있다.
140. `CREATE SEQUENCE SEQ_TEST START WITH 100 INCREMENT BY 5 MAXVALUE 110 NOCYCLE;`
141. `NEXTVAL`은 다음 값을 발급하고 시퀀스를 진행한다. `CURRVAL`은 현재 세션에서 마지막으로 발급받은 값을 반환한다.
142. `10`, `13`, `16`.
143. **얻지 못한다.** 해당 세션에서 먼저 `NEXTVAL`을 호출해야 `CURRVAL`을 사용할 수 있다.
144. `INSERT INTO MEMBER (ID,NAME) VALUES (SEQ_MEMBER.NEXTVAL,'가람');`
145. `ALTER SEQUENCE SEQ_TEST INCREMENT BY 10;`
146. `START WITH`는 `ALTER SEQUENCE`로 직접 변경할 수 없다. 기존 시퀀스를 삭제한 뒤 새 시작값으로 다시 생성한다.

## J. JDBC (147~160)

147. Java 프로그램이 데이터베이스에 연결하고 SQL을 실행하도록 하는 표준 API다.
148. JDBC API는 Java 쪽 표준 인터페이스, JDBC 드라이버는 이를 특정 DBMS와 통신하도록 구현한 라이브러리, DBMS는 데이터를 저장·조회·수정하는 서버다.
149. 드라이버 등록 → 연결 획득 → Statement 생성 → SQL 실행 → 결과 처리 → 자원 닫기.
150. `Class.forName("oracle.jdbc.driver.OracleDriver");`
151. `Connection conn = DriverManager.getConnection("jdbc:oracle:thin:@127.0.0.1:1521:XE", "student", "student");`
152. `Connection`: DB 연결과 트랜잭션 관리. `Statement`: SQL 실행. `ResultSet`: SELECT 결과 행을 커서로 순회하고 열 값을 읽음.
153. (a) `executeQuery()`, (b) `executeUpdate()`.
154. `ResultSet rs = stmt.executeQuery("SELECT EMP_ID, EMP_NAME FROM EMPLOYEE");`
155. `while (rs.next()) { System.out.println(rs.getString("EMP_NAME")); }`
156. `PreparedStatement`는 SQL에 `?`를 놓고 `setString`, `setInt` 등으로 값을 바인딩한다. 같은 SQL 구조에 값을 바꿔 넣기 쉽고, 사용자 입력을 SQL 문법과 분리해 SQL 삽입 위험도 낮춘다.
157. `String sql = "INSERT INTO MEMBER (ID,NAME) VALUES (?,?)"; PreparedStatement ps = conn.prepareStatement(sql); ps.setString(1,id); ps.setString(2,name); int count = ps.executeUpdate();` 사용 후 `ps`를 닫는다.
158. 자리표시자 인덱스는 **1부터** 시작하므로 `ps.setString(1,id)`로 바꾼다. SELECT는 `executeQuery()`가 `ResultSet`을 반환하므로 `ResultSet rs=ps.executeQuery();`로 바꾼다.
159. `Class.forName`에서 드라이버 클래스를 찾지 못하면 `ClassNotFoundException`, DB 연결·SQL 실행 등 JDBC 작업이 실패하면 `SQLException`을 처리한다.
160. 예시:

    ```java
    Statement stmt = conn.createStatement();
    ResultSet rs = stmt.executeQuery("SELECT COUNT(*) FROM MEMBER");
    if (rs.next()) {
        System.out.println(rs.getInt(1));
    }
    rs.close();
    stmt.close();
    conn.close();
    ```

    실제 프로그램에서는 예외가 나도 닫히도록 `finally` 또는 `try-with-resources`를 쓸 수 있다.
